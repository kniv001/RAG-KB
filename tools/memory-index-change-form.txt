# 项目记忆索引（**变化式**：箭头左边是曾经，右边是现在）

- 连接方案：WebRTC 隧道 → 淘汰；存活 Tailscale / CF Tunnel / IPv6 直连（浏览器访问放哪未定）
- 输出方式：自由文本 → 结构化 JSON（plan 从 51.5s 压到 0.94s）
- 语料：294 段 → 812 段（39 篇联网入库）；抓 CSDN 撞 521 → 改用 site: 限定
- 检索质量：无法判定 → 有了召回基准（单跳 15/15）
- 窗口上限：以为就是配置值 10240 → 实测两个模型同驻可到 24576~28672，32768 才崩
- KV 流式：设想可行 → 判死（KV 放系统内存被 PCIe 带宽钉在 ~10 tok/s）
- DP 选块：设想有收益 → 判死（现状下候选全部装得下，收益为 0）
- 命题改写：设想能提信息密度 → 判负（模型只切分在覆盖/速度/失败模式上全面胜出）
- 段检索 + 父块注入：设想两全 → 判死（密度回来了，漏也回来了）
- 分块边界：按字符硬切 → 按句子边界（半句开头的块从 75% 降到 13%）
- 检索粒度：以为段更优 → 复测后优势大半被吃掉（只剩紧预算 +1/10 命中）
- 结构化切分：让模型定章 → 判负（局部判断可靠，全局判断不可靠）
- 结构恢复：想从语料里推 → 不通（标题在抓取环节就丢了）→ 改为入库时保留 h1–h6
- 抓取：main.text() 拍平 DOM → 输出 Markdown（只对新文档生效）
- 结构推断方向：继续找编码 → 淘汰（理由是失去需求适配，不是做不到）
- 检索单元自适应扩张：卷积信号的第三种用法 → 无效（中性到负）
- 句子层指向：以为成立 → 判死（余弦与独立裁判两把尺子同判）
- 词语层指向：→ 存活候选（逐字率 98~100%、判别差 93~95% 为正）
- 句子类型打标：用模型 → 用正则（零成本）；判死理由由「模型做不到」改为「不值当」
- 模型的判断力：以为「因果恒 0」是能力边界 → 撤回（它是 think:false + format 的产物）
- 带思考重测：以为判死都要重审 → 分界（退化解消失、信号质量不消失）；抽取开思考无增益
- 上下文记忆：段落式滚动摘要 → 一行一条的条目（实测索引那一行承载大半）
- 记忆架构：滚动摘要 → 索引常驻 + 正文按需召回（用全量的 23% 上下文答对 11/11）
- 记忆的覆盖关系：无 → 未验证（已知风险：被撤回的结论会被当事实端出）
